Lunettes / casque VR

Avec des lunettes FPV ou un casque branché en HDMI (par ex. Fat Shark Dominator), les AirPods font le suivi de la tête et l'image est en relief.

Cockpit en 3D Vidéos 360° en 3D
  1. Branche les lunettes en HDMI : elles apparaissent comme un deuxième écran (Paramètres → Écrans, 1280×720).
  2. Sur les lunettes, choisis le mode « HDMI 3D » (côte à côte).
  3. Ouvre le cockpit ou les vidéos, déplace la fenêtre sur l'écran des lunettes (Super+Maj+→), puis F pour le plein écran.
  4. Tête droite, appuie sur R pour recentrer. La touche 3 passe de la 3D à la 2D.

OpenTrack (jeux Proton / Wine, X-Plane, FlightGear…)

État—
  1. OpenTrack : Input = « UDP over network », port 4242. Démarrer avec Start.
  2. Output : « Wine » (jeux Proton / Wine : DCS, MSFS, IL-2, Elite, Star Citizen… protocole Both, choisir la version de Proton et l'AppID), « X-Plane », « FlightGear », ou « libevdev joystick ».
  3. Les courbes et filtres d'OpenTrack restent utiles ; dans ce cas mettre le lissage ci-dessous à 0. Recentrer ici (ou la touche Center d'OpenTrack).

Manette virtuelle (jeux Linux natifs, sans OpenTrack)

État—
  1. Euro Truck Simulator 2 / American Truck Simulator (natif) : lier le regard aux axes dans controls_linux.sii (guide dans docs/SIMS.md).
  2. War Thunder (natif), FlightGear, X-Plane : lier « regard / vue gauche-droite, haut-bas » aux axes RX / RY de la manette.
  3. Accès à /dev/uinput nécessaire (le même que pour la souris).

Montre Garmin

Incliner le poignet déplace le curseur, une double tape sur la montre clique. Accéléromètre seul, 25 Hz (service BLE 16).

Module Garmin non installé

La liaison avec la montre utilise la bibliothèque garmin-ble, installée à part : .venv/bin/pip install -r requirements-garmin.txt, puis relancer MousePods. garmin-ble est sous licence AGPL-3.0 (MousePods reste sous Apache-2.0) : voir docs/GARMIN.md.

Calibration et inclinaison

Réglages

Limites

  • La montre n'envoie en temps réel que l'accéléromètre : 3 échantillons toutes les 120 ms (24,9 Hz), 12 bits, ±8 g. Pas de gyroscope en direct.
  • On mesure donc l'inclinaison (direction de la gravité), pas la rotation autour de la verticale. Le rendu à 120 Hz lisse les marches de 25 Hz.
  • Latence : ~80 ms de mise en lot dans la montre, plus 130 ms médians (240 ms p95) de rafales BLE.
  • Bras baissé (grosse inclinaison) = pause. Une tape fige le curseur 0,35 s et annule le petit déplacement qu'elle a causé.

What's new

Découvertes

Ce qu'on a appris en rétro-ingénierie — détails dans REVERSE_ENGINEERING.md.
  • Accélération utilisateur [38:44] (gravité retirée, ~1000 = 1 g) : bruit ≈ 0,02 g au repos — assez propre pour le mode Glisse avec remise à zéro à chaque arrêt.
  • MTU L2CAP : avec 672 octets (défaut Linux), les AirPods 3 cachent leurs capteurs ; à 2582 (comme iOS) ils publient devmotion6, accel, gyro, cma, kadabra.
  • Apple RemoteHID (canal RTBuddy 0x800) : chaque capteur est un périphérique HID virtuel. En-tête de sous-paquet u32 : deviceID (7 bits), longueur (10 bits), type (3 bits).
  • HostConnect 00 gg 00 00 | 00 02 00 00 → les AirPods publient leurs capteurs (DeviceConnect + plist + descripteur HID).
  • SetReport feature 1 = Report Interval (µs) sur devmotion6 → flux de mouvement jusqu'à ~200 Hz.
  • Bloc de 58 octets commun aux AirPods 3 et Pro : quaternion Q15 [20:26], gyroscope [26:32] (~0,122 °/s par unité), accélération [38:44], gravité [44:50] (~1000 = 1 g).
  • AirPods Pro 2 : protocole SensorDataWX (protobuf, 0x100000) — ACTIVITY(14) puis DEVMOTION6(16).
